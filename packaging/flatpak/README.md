# Flatpak

The Flatpak is built by CI (`.github/workflows/flatpak.yml`) from the prebuilt Linux Tauri binary;
there is no local Windows build. GitHub Actions is the first real build, because a Flatpak needs a
Linux host with flatpak-builder and the GNOME SDK.

| File                               | Purpose                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `chat.mudrix.desktop.yml`          | Flatpak manifest: prebuilt binary, desktop file, metainfo and icons      |
| `chat.mudrix.desktop.desktop`      | Desktop entry (`mudrix-desktop`, the `chat.mudrix.desktop://` deep link) |
| `chat.mudrix.desktop.metainfo.xml` | AppStream metadata, licence, releases, screenshots                       |
| `stage/`                           | Generated by CI; not committed (the manifest's `type: dir` source)       |
| `shared-modules/`                  | Generated by CI; Flathub's tray library, pinned to a commit              |

The app id is `chat.mudrix.desktop` (the Tauri identifier), the command is `mudrix-desktop`.

## How CI builds it

`Flatpak` can be started by hand, runs on every `v*` tag, and on pull requests that touch
`packaging/flatpak/` or the workflow itself.

1. **build** (`ubuntu-latest`): checkout, Node 22, the pinned Rust toolchain, Tauri's Ubuntu
   libraries, `npm ci --ignore-scripts`, `npm run tokens`, then
   `npm run tauri -w @mudrix/desktop -- build --no-bundle` (release profile; `beforeBuildCommand`
   builds the desktop web UI). It copies `target/release/mudrix-desktop`, the desktop file and
   metainfo, and the 32/128/256/512 px icons from `apps/desktop/src-tauri/icons` into
   `packaging/flatpak/stage`, rewrites the metainfo's release version from `package.json`, and
   uploads the stage as the `flatpak-stage` artifact (one day).
2. **flatpak** (`ubuntu-latest`, in `ghcr.io/flathub-infra/flatpak-github-actions:gnome-51` with
   `--privileged`): downloads the stage and Flathub's `shared-modules` at a pinned commit, then runs
   `flatpak/flatpak-github-actions/flatpak-builder@v6`, producing `mudrix.flatpak` on the `stable`
   branch with the Flathub runtime repository recorded. The shared modules build
   `libayatana-appindicator`, which Tauri's tray dlopens at startup; the GNOME runtime does not
   ship it. An advisory `flatpak-builder-lint` AppStream check runs afterwards, then the bundle and
   its `.sha256` are uploaded.

The artifact is **`mudrix-flatpak-<version>`** (for example `mudrix-flatpak-26.12.4`) and holds
`mudrix.flatpak` and `mudrix.flatpak.sha256`. Nothing is published: the repository has no release
job, so attaching the bundle to the GitHub release is a manual step. Do not create a second release
for it.

## Install the artifact

Download and unzip the artifact on a Linux machine with Flatpak, then:

```sh
flatpak install --user ./mudrix.flatpak
flatpak run chat.mudrix.desktop
```

The bundle names `https://flathub.org/repo/flathub.flatpakrepo` as its runtime repository, so the
GNOME 51 runtime is fetched from Flathub on first install. Check it with
`sha256sum -c mudrix.flatpak.sha256` (the checksum names `mudrix.flatpak`).

## Runtime choice

`runtime-version: '51'` (`org.gnome.Platform` / `org.gnome.Sdk`). Tauri v2 links
`webkit2gtk-4.1`, and the GNOME runtime ships `libwebkit2gtk-4.1.so`; the SDK still builds
`elements/sdk/webkit2gtk-4.1.bst` on the `gnome-51` branch (checked). A newer runtime than 46 is used
because 46 is **end-of-life**, 48 went EOL in March 2026 and 49 in September 2026: pinning 46 would only
produce an unsupported Flatpak with an older glibc than the Ubuntu 24.04 runner that builds the binary.
GNOME 51 is the current stable branch (supported until roughly September 2027) and has a matching
`gnome-51` action image. Bump all three together:

1. `runtime-version` in `chat.mudrix.desktop.yml`,
2. the `container.image` tag in `.github/workflows/flatpak.yml`,
3. `flatpak install flathub org.gnome.Sdk//<version> org.gnome.Platform//<version>` for local builds.

The runtime is also what supplies WebKitGTK, GTK 3 and GStreamer, so the Flatpak does not carry
Ubuntu's WebKitGTK. Voice/video codecs are whatever the runtime's GStreamer plugins provide (the
same set Flathub apps use).

## Building it locally (Linux)

```sh
# 1. The binary, exactly as CI builds it
npm ci --ignore-scripts
npm run tokens
npm run tauri -w @mudrix/desktop -- build --no-bundle

# 2. The same staging CI does
stage=packaging/flatpak/stage
rm -rf "$stage"; mkdir -p "$stage/icons"
install -m755 target/release/mudrix-desktop "$stage/mudrix-desktop"
install -m644 packaging/flatpak/chat.mudrix.desktop.desktop "$stage/"
install -m644 packaging/flatpak/chat.mudrix.desktop.metainfo.xml "$stage/"
install -m644 apps/desktop/src-tauri/icons/32x32.png "$stage/icons/32x32.png"
install -m644 apps/desktop/src-tauri/icons/128x128.png "$stage/icons/128x128.png"
install -m644 apps/desktop/src-tauri/icons/128x128@2x.png "$stage/icons/256x256.png"
install -m644 apps/desktop/src-tauri/icons/icon.png "$stage/icons/512x512.png"

# 3. The same pinned shared modules CI downloads (tray icon library)
curl -sSfL https://github.com/flathub/shared-modules/archive/c91a81101cf9bcf9fc8132e8c3ebed741ad8bae6.tar.gz \
  | tar -xz -C packaging/flatpak
mv packaging/flatpak/shared-modules-c91a81101cf9bcf9fc8132e8c3ebed741ad8bae6 packaging/flatpak/shared-modules

# 4. The runtime, then the build and the bundle
flatpak remote-add --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
flatpak install flathub org.gnome.Sdk//51 org.gnome.Platform//51
flatpak-builder --user --install --force-clean --repo=repo flatpak_app \
  packaging/flatpak/chat.mudrix.desktop.yml
flatpak build-bundle --runtime-repo=https://flathub.org/repo/flathub.flatpakrepo \
  repo mudrix.flatpak chat.mudrix.desktop stable
```

`stage/` is ignored by git. CI sets the metainfo version from `package.json` on every build, so a
stale `<release>` in the repository is harmless.

## Permissions

Network, IPC (WebKit's process), Wayland with an X11 fallback, GPU (`dri`), PulseAudio, the four
document folders (attachments and drag and drop), notifications, portals, the Secret Service, the
app's own D-Bus name and the StatusNotifier watcher for the tray. No host filesystem, no session or
system bus. They are the minimum the Tauri shelf needs; the bundled app still asks for files through
the portal where possible.

## Known limitations

- **Not a Flathub submission.** The app id `chat.mudrix.desktop` ends in a lowercase `.desktop`, which
  Flathub rejects (it would need a Tauri identifier change), the manifest's `type: dir` source is what
  CI needs but Flathub rejects it, and Flathub's linter flags `--own-name=chat.mudrix.desktop` and the
  portal talk-name as unnecessary (Flatpak grants both). That is why the lint step checks only the
  AppStream file and is advisory.
- **x86_64 only.** The binary is built on `ubuntu-latest`; there is no arm64 leg (it would need an
  arm runner and a second bundle).
- **No in-app updates.** Tauri's updater cannot replace a Flatpak; update with `flatpak update`.
  The updater plugin's check may log an error the first time.
- **Tray icon and autostart.** The tray library is bundled from Flathub's shared modules, so the
  app starts and registers with the StatusNotifier watcher; the icon only appears under a
  StatusNotifier host (stock GNOME needs the AppIndicator extension). The autostart plugin still
  writes an entry inside the sandbox that the host will not run.
- **Global shortcuts** are X11 grabs; under Wayland they may not work (portal support is not wired
  up).
- **Unsigned bundle.** CI does not GPG-sign the `.flatpak` (no Flatpak signing key in the repo);
  `flatpak install` warns as it would for any local bundle.
- **Screenshots** point at `raw.githubusercontent.com`; they are not mirrored to Flathub's media
  repository, which a Flathub submission would require.
- **First build is CI.** The manifest cannot be built on Windows; these files were only
  syntax-checked here. If the Flatpak fails, the usual causes are a runtime version bump (see
  above), a missing icon size, a failed `shared-modules` download, or a library the Tauri binary
  links that the runtime does not ship (check the `ldd` output in the build log; the tray library is
  dlopened, so check that the shared module built). If the `gnome-51` container tag is not published
  yet, point `container.image` at the previous tag: the action downloads the runtime and SDK from
  Flathub anyway, the image only saves that download.
