# Mudrix parity matrix

Authoritative gap list between the old JavaScript Mudrix (`E:\code\web\mudrix-web`, plus the `mudrix-desktop` and
`mudrix-mobile` shells) and this Rust-core rewrite (branch `web-look`). Read-only audit, produced 2026-11-11 from the
code, not from docs, and last re-checked against the tree on 2026-11-15. `docs/PORT.md` was the starting index; its
"Port status" tables turned out to be **stale for the web app** (for example `ProfileStyle.tsx` and `ProfileEffect.tsx`
are now line-for-line copies of the old files, and the web has the soundboard, integrations, Modern spaces and cosmetics
UI), so every row below was re-checked against the tree.

The 2026-11-15 pass updated every path to the renamed trees (`apps/android/app/src/main/kotlin/chat/mudrix/android`,
`apps/ios/Mudrix`), marked the Android/iOS parity batches that landed since 2026-11-13, and added `won't-do` as a status
for the rows the owner has deliberately decided against (reasons in `docs/DECISIONS.md`).

## How the audit was done

- Old inventory: every settings page of `src/app/features/settings/**` (option by option via the locale keys each page
  uses), the message context menu, composer, room/space settings, profile, calls, inbox, desktop `src-tauri/src/*.rs`
  and the mobile shell.
- New status: for each feature, file existence plus use of its atoms / RPCs in `apps/web`, `apps/android`, `apps/ios`,
  `apps/desktop`, `crates/core`. Two mechanical cross-checks found most of the gaps: (a) same-named files whose line
  count shrank (`EmojiStickerPanel` 815 -> 386, `PackEditor` 755 -> 519, `About` 305 -> 143, `UserProfilePopup`
  1535 -> 1285, `PollViewer` 322 -> 145, ...), and (b) i18n keys a ported file used in the old app and no longer
  references (`timeline.editHistory.open`, `composer.schedule.menu`, `room.markUnread`, `room.addLowPriority`,
  `room.space.nickname.menu`, `timeline.stickerPack.*`, ...).
- Status words: **done** = equivalent behaviour present; **partial** = exact gap in the Notes; **missing** = nothing
  found; **won't-do** = deliberately not ported, with the user-facing reason in `docs/DECISIONS.md`; **n/a** = the
  platform cannot (or by design does not) have it, reason in Notes.
- **Re-audit 2026-11-13:** every row whose Web, Android or iOS cell was `partial` or `missing` was checked against the
  tree again (the notes had drifted: they described work done after the first pass, or understated what the code now
  does). Rows whose status changed, or whose note was wrong, carry a short "**Audit:**" sentence with the evidence path.
- **Re-audit 2026-11-15:** the Android/iOS parity batches in `git log` (Android Modern shell and media/call work, iOS
  Modern navigation, pre-upload, media and call work, the rename) were checked row by row. Statuses were raised where the
  code now exists (`M6`, `M8`, `M9`, `M11`, `M14`, `A5`, `A7`, `A14`, `C2`, `C4`, `C10`, `C14`, `N6`, `P1`, `P2b`,
  `P10`, `P11`, `P13`, `R2`, `R4`, `R6`, `R12`, `R13`, `R15`, `S4`, `S6`, `T18`, `T19`, `K1`, `K4`, `K6`, `K8`,
  `K10`, `K12`, `D7`, `E1`, `Y6` and the baseline `B1-B9`), lowered where the check found a real gap (`M7` on iOS,
  `A8` on both natives, `P2c` and `R9` on iOS, `C15` on iOS, `K8` on web) and `won't-do` was added for `N1` (iOS),
  `X1` (native), `X2` (web) and `R8` (all). Every row now names the file that shows its state.
- **Re-audit 2026-11-16:** the Android fixes from the scenario report were applied and checked on the device: `A8`, `K1`, `K6` and `K12` moved from `partial` to `done`; the delete confirmation (`T18`), the Inbox thread filters and thread back path (`R13`), the Cosmetics page (`P2b`), the bubble layout (`A6`) and the debug-only cleartext for the local test stack (`Y6`) are noted in their rows. The iOS cells were not touched.
- **Caveat for iOS:** every iOS row marked done/partial was written on Windows and has never been compiled or run (see
  `PORT.md` "iOS port status"). Android rows are compiled and unit-tested but most UI is unverified on a device.
  "Done" on those platforms means "code present", not "tested".
- Web and desktop share one column: the desktop app is the web app in Tauri, so a web gap is a desktop gap; desktop-only
  rows (section 12) say so.
- Native apps now have both shells: Modern (default) and Classic. "Android / iOS: missing" is a request to port the
  _behaviour_ natively.

## Needs owner / impossible

1. **Import room keys (and export on web)** (K8, T8). matrix-rust-sdk 0.19 only imports / exports key files from a file
   _path_, does not exist on wasm, and keeps the `OlmMachine` private; the only route is the `testing` feature, which is
   not acceptable. Export / import is now done on desktop and mobile through a file path in core native builds only.
   Impossible today: web (decision: `won't-do`). Needs an SDK change upstream to change that.
2. **KLIPY provider** (M11): **done.** `VITE_KLIPY_API_KEY` is a repository secret, and every workflow that builds an
   app embeds it (web/desktop `VITE_KLIPY_API_KEY`, Android `BuildConfig.KLIPY_API_KEY`, iOS `WZKlipyApiKey`); the tab
   appears when the embedded key is non-empty.
3. **Push notifications on iOS** (Y3, N3): APNs requires an Apple Developer account, a push entitlement and a push
   gateway that talks to Apple (Sygnal or equivalent). Mudrix has both an APNs pusher and a background keep-alive with
   local notifications (compile-time `WZ_PUSH_MODE`). Owner decision (2026-11-16): there is no Apple Developer account,
   so the APNs route is out of scope; iOS uses the background keep-alive with local notifications.
4. **Android push without Google** (Y1): the three modes are implemented (`-Pmudrix.push=keepalive|unifiedpush|fcm`).
   UnifiedPush still needs a distributor choice and a gateway URL; FCM needs `google-services.json` (Firebase project)
   for the `gplay` flavour. Both are credentials, not code.
5. **Legal: Discord-scraped cosmetics** (P2, P2b): answered — the art shipped in the repo is original, the sync script
   stays user-run and is not a supported feature, and no scraped packs ship in the repo or default config
   (`DECISIONS.md`). Keep the script's own warning intact.
6. **Legal: games database** (P5): answered — game detection stays and is built upon (`DECISIONS.md`); the Windows-only
   `activity/games.json` stays desktop-only.
7. **Legal / licences of bundled sounds**: 14 packs include sounds taken from Element, Cinny, FluffyChat, Commet and
   console-style packs (Mega Drive / NES). `packages/sounds/LICENSES.md` exists; owner should confirm it is complete
   before store release.
8. **Signing**: Android release APKs use the old `mudrix-release.keystore` and desktop upgrade artifacts use the old
   `mudrix-updater` minisign key, so existing installs continue to update in place. Windows code signing and macOS
   notarisation are still absent, and iOS has no signing at all: there is no Apple Developer account, so it stays
   Simulator-only (no device install, TestFlight, App Store or APNs).
9. **Widgets** (I5): in scope by owner decision, but not started on native. Web has the sandboxed widget stack and the
   core has a widget driver (`crates/core/src/widgets.rs`); Android and iOS need a WebView host with the same capability
   bridge, after the security review.
10. **Namespace**: new data is written as `io.github.kapsikkum.mudrix.*` and the older `chat.mudrix.*` and
    `org.wizardchat.*` names are read but never written, except where another device may still need an older one
    (settings). The custom status follows this rule (write `io.github.kapsikkum.mudrix.status`, read the old names); the
    watch-together topic still writes the Mudrix name and reads WizardChat's. The old names are permanent compatibility,
    see `docs/DECISIONS.md`.
11. **Session name** (D14): answered — sessions register as "Mudrix Desktop" / "Mudrix Web" / "Mudrix Android" /
    "Mudrix iOS" (`core/client.ts`), and the branding gate enforces it.
12. **Server-dependent features**: T1 (send later) needs MSC4140 on the homeserver; P8 homeserver software badge only
    works in browsers for servers that allow cross-site federation GETs; M3/N4 depend on the server's media config.
13. **Rust-SDK sliding sync cannot deliver arbitrary custom state** (R1, R2, R3, R4, S5): answered for Mudrix's own
    state — `crates/core/src/custom_state.rs` opens a second light sync for the eight Mudrix state types and exposes
    `stateEventsWithSender` / `watchStateEvents`, so no polling. Role changes in the audit log still need
    `showStateEventTypes` (R4, iOS); everything else uses `EntryContent.State` from the timeline.
